# Отчёт

## 1. Стек технологий мониторинга

* **Хранилище метрик (TSDB):** VictoriaMetrics Single (`vm-single`, Helm-чарт `vm/victoria-metrics-single`) — прием, хранение и обработка метрик по протоколам MetricsQL / PromQL (порт `8428`).
* **Агент сбора метрик:** VictoriaMetrics Agent (`vmagent`, Helm-чарт `vm/victoria-metrics-agent`) — периодический pull-сбор метрик с обнаруженных таргетов и передача в TSDB через протокол Remote Write (порт `8429`).
* **Обнаружение сервисов (Service Discovery):** Kubernetes Service Discovery (`kubernetes-pods`) — автоматическое обнаружение подов для сбора метрик по аннотациям `prometheus.io/scrape`, `prometheus.io/port`, `prometheus.io/path`.
* **Экспорт метрик рантайма и бизнес-метрик:**
  * Spring Boot Actuator (`spring-boot-starter-actuator`) — модуль мониторинга и телеметрии приложения.
  * Micrometer Prometheus Registry (`io.micrometer:micrometer-registry-prometheus`) — формирование метрик рантайма JVM и доменных счетчиков в стандарте OpenMetrics (эндпоинт `/actuator/prometheus`).
* **Экспорт метрик СУБД:**
  * `prometheuscommunity/postgres-exporter:v0.15.0` — официальный sidecar-экспортёр PostgreSQL, преобразующий системную статистику БД в формат Prometheus (порт `9187`, эндпоинт `/metrics`).
* **Среда оркестрации:** Kubernetes v1.39.0 (Minikube).

## 2. Использованные экспортёры

В рамках выполнения задания реализована Pull-модель сбора метрик при помощи двух типов экспортёров:

### 2.1. Встроенный экспортёр Spring Boot Actuator + Micrometer
Для компонентов бэкенда (`backend-api` и `backend-worker`) задействован встроенный механизм Spring Boot Actuator совместно с библиотекой Micrometer Prometheus:
* **Эндпоинт метрик:** `http://<pod-ip>:8080/actuator/prometheus` (формат OpenMetrics / Prometheus text format).
* **Конфигурация:** В `application.yml` активирован экспорт эндпоинта `prometheus` (`management.endpoints.web.exposure.include: health,info,prometheus,metrics`), включен сбор MBean-метрик встроенного сервера Tomcat (`server.tomcat.mbeanregistry.enabled: true`) и построение гистограмм квантилей для HTTP-запросов (`management.metrics.distribution.percentiles-histogram.http.server.requests: true`).
* **Метрики рантайма и фреймворка:**
  * Состояние JVM: память (`jvm_memory_used_bytes`, `jvm_memory_max_bytes`), потоки (`jvm_threads_live_threads`), сборщик мусора (`jvm_gc_pause_seconds`).
  * Пул соединений HikariCP: активные, ожидающие и простаивающие соединения (`hikaricp_connections_active`, `hikaricp_connections_idle`, `hikaricp_connections_pending`).
  * Веб-сервер Tomcat и сетевые запросы: общее количество, длительность и статус-коды HTTP-ответов (`http_server_requests_seconds_count`, `http_server_requests_seconds_sum`).
  * Системные ресурсы контейнера: загрузка CPU (`process_cpu_usage`, `system_cpu_usage`), дескрипторы файлов (`process_files_open_files`).

### 2.2. Готовый экспортёр PostgreSQL (Sidecar-контейнер)
Для мониторинга СУБД PostgreSQL использован официальный контейнер `prometheuscommunity/postgres-exporter:v0.15.0`:
* **Архитектура:** Развёрнут как sidecar-контейнер внутри Pod'а `postgres` в `k8s/postgres.yml`. Благодаря общему сетевому пространству пода (`localhost`), экспортер подключается напрямую к порту `5432` СУБД с минимальными задержками и без выставления порта СУБД наружу.
* **Эндпоинт метрик:** `http://<pod-ip>:9187/metrics`.
* **Переменные окружения:**
  * `DATA_SOURCE_URI`: берется из `ConfigMap` `uchebny-radar-config` со значением `localhost:5432/uchebny_radar?sslmode=disable`.
  * `DATA_SOURCE_USER`: берется из `ConfigMap` со значением пользователя `postgres`.
  * `DATA_SOURCE_PASS`: берется из `Secret` `uchebny-radar-secret`.
* **Собираемые метрики СУБД:**
  * Фиксация транзакций и откаты: `pg_stat_database_xact_commit`, `pg_stat_database_xact_rollback`.
  * Активность сессий: `pg_stat_activity_count`.
  * Блокировки и конфликты: `pg_locks_count`.
  * Размеры таблиц и базы данных: `pg_database_size_bytes`.

## 3. Бизнес-метрики доменной области приложения

В исходный код приложения «Учебный радар» интегрированы **5 кастомных бизнес-метрик** на базе Micrometer `Counter`:

| Метрика в OpenMetrics | Имя в коде Micrometer | Теги (Labels) | Класс реализации | Описание бизнес-события |
| :--- | :--- | :--- | :--- | :--- |
| `projects_total` | `projects_created_total` | *нет* | `ru.uchebnyradar.project.ProjectService` | Инкрементируется при каждом успешном создании нового проекта пользователем (`createProject`). |
| `tasks_total` | `tasks_created_total` | `priority` (`low`, `medium`, `high`) | `ru.uchebnyradar.task.TaskService` | Инкрементируется при создании учебной задачи (`createTask`) с фиксацией ее приоритета. |
| `tasks_completed_total` | `tasks_completed_total` | *нет* | `ru.uchebnyradar.task.TaskService` | Инкрементируется в методе `updateStatus` при переводе задачи в статус `COMPLETED`. |
| `user_registration_total`| `user_registration_total`| `status` (`success`, `failure`) | `ru.uchebnyradar.auth.AuthService` | Фиксирует попытки регистрации пользователей: успешные создания аккаунта (`success`) и отказы из-за дубликата логина (`failure`). |
| `reminders_processed_total`| `reminders_processed_total` | *нет* | `ru.uchebnyradar.reminder.ReminderWorker` | Фиксирует количество обработанных и отправленных напоминаний фоновым планировщиком (`processReminders`). |

> **Примечание по наименованию OpenMetrics:** Согласно стандарту OpenMetrics, суффикс `_created` зарезервирован для служебных временных меток создания временного ряда. Поэтому Prometheus-форматтер Micrometer автоматически преобразует имя `tasks_created_total` в имя временного ряда `tasks_total`, сохраняя семантику типа `counter`.
