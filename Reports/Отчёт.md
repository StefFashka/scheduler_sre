## 1. Выбор компонентов

Для доставки логов выбран **Vector в виде DaemonSet**, собирающий логи из `/var/log/pods` и отправляющий их в Victoria Logs через Elasticsearch Bulk API:

* **DaemonSet вместо Sidecar:** один агент на ноду вместо копии в каждом поде — минимальное потребление CPU/RAM и надёжный сбор логов даже при аварийном падении приложения.
* **Vector (Rust):** потребляет всего ~30–50 МБ RAM, работает без GC-пауз и нативно парсит JSON из `stdout` прямо в памяти через язык VRL (`parse_json(.message)`).
* **Маппинг полей Victoria Logs:** параметры `_msg_field="message"`, `_time_field="timestamp"` и `_stream_fields="pod_name,container_name"` позволяют не менять схему логов приложения и формируют компактные стримы с высокой степенью сжатия данных (Stream Locality).

## 2. LogsQL-запросы в vmui (п.4)

### Запрос 1: Сырые записи за временное окно
```logsql
_time:30m service.name:"uchebny-radar-backend"
```
* **Описание:** Все сырые события бэкенда за последние 30 минут без применения агрегаций. Фильтр `_time:30m` отсекает старые партиции и ускоряет чтение с диска. В результатах видны системные логи старта Spring Boot и попытки аутентификации.

![Запрос 1: Сырые записи](../artifacts/Снимок%20экрана%202026-10-16%20225902.png)

---

### Запрос 2: Фильтр по конкретному полю
```logsql
_time:30m level:WARN
```
* **Описание:** События только с уровнем `WARN` за последние 30 минут благодаря колоночной фильтрации по распарсенному JSON-полю `level`. Показывает предупреждения Hibernate и события неверных учетных данных (`Authentication failure: Bad credentials`).

![Запрос 2: Фильтр по полю level](../artifacts/Снимок%20экрана%202026-10-16%20230104.png)

---

### Запрос 3: Stats-запрос с группировкой
```logsql
_time:30m | stats by (kubernetes.container_name, level) count() as total
```
* **Описание:** Подсчет общего количества записей (`total`) с одновременной группировкой по имени контейнера (`kubernetes.container_name`) и уровню логирования (`level`). Позволяет мгновенно оценить распределение объёма логов по микросервисам (grafana, frontend, backend-api, backend-worker, vector, postgres).

![Запрос 3: Группировка stats](../artifacts/Снимок%20экрана%202026-10-16%20230141.png)

---

### Запрос 4: Агрегирующий запрос (Топ источников)
```logsql
_time:30m | top 5 by (logger)
```
* **Описание:** Топ-5 наиболее активных Java-логгеров (классов) за 30 минут. Показывает классы `org.hibernate.orm.deprecation`, классы подсистемы Spring Security и `ru.uchebnyradar.common.GlobalExceptionHandler`. Позволяет быстро выявлять наиболее шумные компоненты системы.

![Запрос 4: Топ источников](../artifacts/Снимок%20экрана%202026-10-16%20230233.png)
